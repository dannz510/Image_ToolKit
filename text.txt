Hệ thống được thiết kế theo mô hình **Client-Side Heavy Architecture** (Xử lý nặng tại phía máy khách), chia làm 3 tầng rõ rệt:

* **Nhiệm vụ:** Lưu lịch sử thao tác (Undo/Redo Stack), cache mô hình AI sau lần tải đầu tiên để lần sau chạy offline hoàn toàn không cần mạng.

### 1. Neural Synapse Pulse (Mạng lưới thần kinh AI quét tâm trí)

* **Cảm hứng:** Giống như các phân cảnh AI đang "suy nghĩ" trong phim khoa học viễn tưởng.
* **Cách hoạt động:** Khi người dùng bấm nút xóa nền, bức ảnh gốc chuyển sang dạng **lưới trắng đen (Monochrome Grid)**. Một mạng lưới các điểm nút (Nodes) xuất hiện và phát sáng theo dạng xung điện (Pulse), lan tỏa từ tâm chủ thể ra các viền xung quanh. Các đường viền tóc hay chi tiết nhỏ được "khóa" lại bằng các tia sáng xanh nhấp nháy trước khi phần nền xung quanh tan biến.
* **Công nghệ:** SVG Path animation kết hợp hiệu ứng Glow bằng CSS/Canvas.

### 2. The 3D Wireframe Laser Scan (Tia quét laser không gian chiều sâu)

* **Cảm hứng:** Công nghệ quét địa hình hoặc CAD engineering.
* **Cách hoạt động:** Bức ảnh được dựng lên thành một mặt phẳng 3D nghiêng nhẹ (dùng Three.js). Một đường kẻ laser màu xanh dương hoặc neon chạy dọc từ trên xuống dưới bề mặt ảnh. Ngay tại vệt laser đi qua, phần nền được bóc tách lập tức thành dạng lưới khung dây (Wireframe) rồi biến mất, chỉ để lại phần chủ thể sáng bóng giữ nguyên màu sắc thực.
* **Công nghệ:** Three.js (`MeshBasicMaterial` kết hợp wireframe shader).

### 3. Particle Dissolve & Reassemble (Hiệu ứng hạt phân rã & hội tụ)

* **Cảm hứng:** Hiệu ứng Thanos búng tay hoặc phân rã dữ liệu số.
* **Cách hoạt động:** Ngay khi tiến trình bắt đầu, toàn bộ các pixel thuộc phần nền (background) của ảnh vỡ vụn thành hàng nghìn hạt bụi kỹ thuật số (Particles) bay lơ lửng và tan biến vào hư vô. Trong khi đó, các hạt thuộc về chủ thể được hút ngược lại và hội tụ chặt chẽ với nhau để tạo thành bức ảnh hoàn chỉnh cuối cùng.
* **Công nghệ:** Three.js `Points` hoặc HTML5 Canvas Pixel Manipulation.

### 4. The X-Ray Depth Layer Peel (Bóc lớp kính Hologram lớp-lớp)

* **Cảm hứng:** Giao diện bóc tách linh kiện của Apple hoặc kính thực tế ảo AR.
* **Cách hoạt động:** Bức ảnh được tách thành 3 lớp trong suốt (Glass Layers) xếp chồng lên nhau theo trục Z. Lớp đáy là background gốc dịch chuyển lùi ra xa và mờ dần. Lớp giữa là bản đồ độ sâu (Depth Map) hiển thị dạng ma trận số học chạy chữ liên tục. Lớp trên cùng là chủ thể chính được đẩy nổi lên phía trước với hiệu ứng viền sáng (Rim lighting) bao bọc.
* **Công nghệ:** CSS 3D Transform (`perspective`, `translateZ`) kết hợp hiệu ứng đổ bóng động.

## 🛠️ Hướng 1: Hybrid Architecture (Python Serverless API + Modern Frontend)

*Phù hợp nếu muốn tận dụng hệ sinh thái Python (Pillow, OpenCV, PyTorch/ONNX) xử lý ở Backend.*

### 1. Cơ chế hoạt động & Hạ tầng Vercel

* **Frontend:** Viết bằng React/Vite/Next.js (hoặc Tailwind CSS + Three.js), biên dịch thành static asset cực nhanh, được Vercel phân phối qua CDN toàn cầu.
* **Backend:** Sử dụng tính năng **Vercel Serverless Functions (Python Runtime)**. Đặt các script Python trong thư mục `/api/*.py`. Vercel sẽ tự động biến các file này thành RESTful API Endpoint (FastAPI hoặc Flask wrapper).

### 2. Cấu trúc thư mục dự án (Directory Structure)

```text
dannz-ai-studio/
├── api/
│   ├── remove_bg.py       # Vercel Python Serverless Function (Rembg/ONNX)
│   └── requirements.txt   # Danh sách thư viện Python nhẹ (rembg, pillow, numpy)
├── src/
│   ├── components/        # UI Components (Canvas, 3D Viewport, Layer Panel)
│   └── main.js            # App Entrypoint
├── public/                # Assets, Icons, Shaders
├── vercel.json            # Cấu hình routing & Serverless execution timeout
└── package.json           # Frontend dependencies (Three.js, Lucide-react)

```

### 3. Cách triển khai Code Backend (`/api/remove_bg.py`)

Sử dụng **FastAPI** hoặc **BaseHTTPRequestHandler** để xử lý request cực nhẹ:

```python
from http.server import BaseHTTPRequestHandler
from rembg import remove, new_session
import io

# Khởi tạo session AI Core (Tự động cache trong vòng đời Serverless Instance)
session = new_session("u2netp") # Dùng u2netp để tối ưu dung lượng và tốc độ

class handler(BaseHTTPRequestHandler):
    def do_POST(self):
        content_length = int(self.headers['Content-Length'])
        post_data = self.rfile.read(content_length)
        
        # Xử lý bóc tách nền
        output_data = remove(post_data, session=session)
        
        # Tra cứu kết quả về Client
        self.send_response(200)
        self.send_header('Content-Type', 'image/png')
        self.end_headers()
        self.wfile.write(output_data)

```

### 4. Giới hạn cần lưu ý trên Vercel Serverless (Python)

* **Execution Timeout:** Vercel Hobby plan giới hạn thời gian chạy của 1 Serverless Function là **10 giây**. Do đó phải dùng model AI thật nhẹ (như `u2netp` hoặc `onnxruntime-web`) để xử lý dưới 2-3s.
* **Payload Size:** Giới hạn dung lượng request tải lên tối đa **4.5 MB**. Muốn xử lý ảnh lớn hơn, Client phải resize nhẹ trước khi gửi lên API.

## ⚡ Hướng 2: Pure Client-Side Architecture (WebGPU / WASM + Python Local Option)

*Đây là hướng đi **Zero-Cost chuẩn đét 100%**, hoàn toàn né được giới hạn Serverless của Vercel.*

### 1. Cơ chế hoạt động

* Deploy toàn bộ Web App (HTML/JS/Three.js/ONNX Web Runtime) lên Vercel dạng **Static Web Site**.
* Khi người dùng kéo thả ảnh, **mô hình AI `.onnx` được tự động tải về trình duyệt** và chạy trực tiếp trên card đồ họa (GPU/CPU) của người dùng bằng **WebGPU / WebAssembly (WASM)**.
* **Serverless Vercel chỉ làm nhiệm vụ cấp file static (0% CPU Server tốn kém)**.

### 2. So sánh 2 Hướng Deploy lên Vercel

| Tiêu chí | Hướng 1: Hybrid (Python Serverless API) | Hướng 2: Pure Client-Side (WebGPU/WASM) |
| --- | --- | --- |
| **Nơi xử lý AI** | Trên Serverless Cloud của Vercel | Trực tiếp trên GPU máy tính người dùng |
| **Giới hạn file ảnh** | Dưới 4.5 MB (Giới hạn Vercel) | Không giới hạn (Tùy thuộc RAM máy tính) |
| **Độ trễ (Latency)** | Tốn thời gian upload/download ảnh | 0ms độ trễ mạng (Xử lý Offline) |
| **Khả năng dính Lỗi Timeout** | Có (nếu ảnh quá nặng > 10s) | Không bao giờ bị timeout |
| **Đánh giá phù hợp** | Phù hợp làm MVP kết nối Python sẵn có | **Hoàn hảo nhất cho Local-First / Zero-Dollar Studio** |

## 🚀 Các Bước Triển Khai Deploy Lên Vercel (Deployment Steps)

1. **Chuẩn bị file `vercel.json` cấu hình Build:**
```json
{
  "builds": [
    { "src": "api/*.py", "use": "@vercel/python" },
    { "src": "package.json", "use": "@vercel/static-build" }
  ],
  "routes": [
    { "src": "/api/(.*)", "dest": "/api/$1" },
    { "src": "/(.*)", "dest": "/$1" }
  ]
}

```


2. **Đẩy code lên GitHub Repository.**
3. **Kết nối Repository với Vercel Dashboard:**
* Chọn `Import Project` $\rightarrow$ Chọn Repo GitHub.
* Vercel tự động nhận diện file Python và Frontend để build chỉ trong 1-2 phút!
